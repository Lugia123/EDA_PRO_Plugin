# 用地图画原理图

## 分工：你管语义，算法管几何

以前是你逐个器件算坐标、定角度、错开标签。那条路的天花板很低 ——
十几个器件的位置互相牵制，线长、交叉、重叠、朝向几项彼此拉扯，手算算不过来。

现在换成：

```
你  → 用什么器件、分几个功能区、哪个脚连哪个脚、每条网络是信号还是电源地
算法 → 器件摆哪、转多少度、翻不翻面、线怎么走、文字往哪放
```

**别再手工指定坐标和角度**。你给个大致位置就行，甚至不给也可以。

## 地图是什么

一份 JSON，存在原理图里（一个带标记的文字图元），所以换机器、换人打开都还在。
结构见 `src/layout/map.ts`，要点：

| 字段 | 谁填 | 说明 |
|---|---|---|
| `parts[].w/h/pins` | **EDA** | 符号尺寸与引脚，库里的客观事实，别凭记忆写 |
| `parts[].place` | 算法 | 位置、角度、镜像 |
| `parts[].group` | **你** | 归哪个功能区 |
| `parts[].labels[].dx/dy` | 算法 | 文字往哪摆 |
| `nets[].pins` | **你** | 谁连谁 |
| `nets[].kind` | **你** | signal / power / ground / analog_ground |
| `nets[].style` | 你或默认 | wire 画线 / symbol 放符号 / port 端口 |
| `groups[].anchor` | **你**（可选）| 期望的区位置，给了就锁死 |
| `groups[].box` | 算法 | 按实际占用量出来的框 |

## 标准流程

```
① eda_map_import      从现有图生成地图初稿（新图则自己写）
② 补语义              网络性质、分区归属、层号 —— 这步只有你能做
③ eda_map_verify      核对几何。手写过 pins 或 w/h 的话**必跑**
④ eda_map_save        存进图纸
⑤ 逐层 apply          见下节。简单图可以一次画完，复杂图务必分层
⑥ eda_check_schematic 体检
```

## 逐层递进：一层层长出来，不要一次算完

一次性摆完所有器件再连线，等于**把所有约束堆到最后同时求解** —— 退火只能
在一个巨大的解空间里找折中，而且芯片的引脚展开区排在最后，只能在别人留下的
缝里挤。人画图从来不这样：放一点、连一点、看一眼、再放下一层。

```
第 1 层  核心芯片        eda_map_apply({ layer: 1 })
         ↓ 这层占掉的地方（器件 ＋ 引脚展开区 ＋ 走线）成为硬约束
第 2 层  它的外围器件    eda_map_apply({ layer: 2, incremental: true })
         ↓
第 3 层  ……
```

在地图的 `part.layer` 上写层号，不写默认第 1 层。

**为什么必须这样**：芯片的引脚展开区是芯片的一部分，该由**别人避开它**。
只有先把芯片和它的扇出摆定，后面的器件才会被布局算法挡在外面。反过来做，
扇出就得自己去躲，怎么补避让都是治症状。

### 怎么分层

| 层 | 放什么 | 判断依据 |
|---|---|---|
| 1 | 核心芯片（MCU、稳压器、运放……） | 引脚最多、决定整块布局骨架的那个 |
| 2 | 直接挂在核心上的外围 | 去耦电容、上下拉、晶振 |
| 3 | 再外一圈 | 指示灯、按键、接插件 |

同一层内部还可以用 `group` 分区，两者是正交的：**layer 决定先后，group 决定
聚在一起**。

### 每层画完必须看什么

`eda_map_apply` 返回里这几项，一项不对就别画下一层：

- `parts_placed_verified` —— 器件真的挪到算法要求的位置了吗（false 说明写入没生效）
- `endpoint_mismatches` —— 导线端点有没有落在引脚上，**必须是 0**
- `unrouted` —— 有没有连不通的
- `trace.lines` —— 分区重叠、越出图纸、某步写失败，都会在这里点名

然后跑 `eda_check_schematic` 看 `broken` / `shorts`。**短路最要命**：
DRC 不报、肉眼也看不出，只有连通性模型查得到。

### 第一层之后都要加 incremental

不加的话每次 apply 都会清场重画，把前面层的成果抹掉。代价是同一层**只能
渲染一次** —— 重复 apply 同一层会产生重复图元。要重来就全量跑一遍
（不传 layer、不传 incremental）。

### 网络性质必须你来判定

`eda_map_import` 会按名字猜一个 kind，**那只是初稿，务必逐条过目**。
名字判断不了这些：

- `AVDD_1V8`、`VBAT_SW`、`VREF_2V5` —— 既像电源又像信号
- `PWR_EN` —— 听着像电源，其实是普通 IO
- `VSENSE`、`ISENSE` —— 是模拟信号，不是电源

判错的代价：电源被当信号会去画线（本该放符号），信号被当电源会挂个符号上去。

### 性质决定画法

| kind | 画成什么 | 为什么 |
|---|---|---|
| signal，两端同区 | 导线 | 块内连接要看得见 |
| signal，跨区 | IN/OUT 端口 | 长线穿越图纸是可读性头号杀手 |
| power / ground | 电源符号、地符号 | 同名自动相连，还省掉最大量的文字 |

跨区网络算法会自己识别（两端不在同一 group），不用你标。

## 分区是分治的单位

功能区先是一种**布局手段**，其次才是图上那个框：

```
组内 —— 每组在一片空地上独立优化，只看本组器件与组内连线。
        十几个器件的问题降成四五个，退火收敛质量高一个量级。
组间 —— 每组塌缩成一个已知尺寸的矩形，跨组连接多的靠得近。
```

**框是布局的产物**，等组内摆完按实际占用量出来再画，不是预先划一块地往里塞。

### 你的终审：只调组间，不碰组内

算法只认线长、交叉、重叠，不懂阅读习惯 —— 信号从左往右流、电源区在左上、
接口贴图纸边缘、相关的区要挨着。这些只有你知道，所以最后一步是你的。

先跑一次 `eda_map_apply` 带 `dry_run`，看返回里每个区的尺寸，
再给 `groups[].anchor` 指定位置。**组内布局不要干预**，那是纯几何，算法比手算准。

装不下时它会明说：「所有分区横向共需 1510，图纸只有 1415 可用」、
「分区 io 越出图纸 —— 它的位置是指定的 (1350,300)，而该区实际占 880×660」。
照着挪 anchor，或者换更大的图纸。

## 几个绕不开的坑

- **一个标签页里开了多个文档时，MCP 操作的是「当前活动文档」**，而它可能在你
  不知道的时候切换。每次开工先 `eda_current_context` 确认页面，别凭 URL 判断。
- **页面刚加载完就调工具会读到空**。先确认能读到器件再往下走。
- **`eda_map_apply` 不要连着调第二次**。它靠清场重画，而删图元会让扩展断连，
  断在中途会把上一次的成果破坏掉（实测悬空引脚从 0 变成 20）。
  要重新布局，先确认图是干净的。
- **改过图纸尺寸，体检要传 `sheet`**。`titleBlockData` 里的尺寸字段常读不到，
  读不到就退回 A4，于是 A3 上画的图会被误判成大面积出框。
- **DRC 不能当连接的证据**。它查已有网络之间的冲突，查不出引脚压根没进网络。
  连接看 `eda_check_schematic` 的 `floating_unexpected`。

## 什么时候不用地图

改一两个器件的位置、加一个电容、调一根线 —— 直接用 `eda_arrange_components`、
`eda_wire_block` 这些单点工具更快。地图适合的是整张图的布局，或者要反复优化的场合。
