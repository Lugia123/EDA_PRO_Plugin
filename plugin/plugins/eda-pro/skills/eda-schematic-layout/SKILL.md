# 原理图布局与分区

> **要整张图布局或重排，先看 `eda-schematic-map`** —— 那套做法是你只给语义
> （谁连谁、分几个区、网络性质），位置角度走线全交给算法，比手工算坐标可靠得多。
> 这份文档留给两种场合：**理解为什么这么排**（下面的分区划法、头对头、图纸惯例
> 都是代价函数的依据），以及**手工微调**单个器件时的准则。

## 设计顺序：从需求出发，一个区一个区地做完

**不要"全部放器件 → 全部连线 → 全部布线"**。那样等于先摆一堆零件再想怎么接，
方向必然乱，线只能绕。正确的节奏是**逐区闭环**：

```
① 理解需求          这块板要实现什么？输入什么信号、输出什么、供电几伏？
② 选主芯片          按功能选核心器件：MCU、运放、ADC/DAC、转换器、收发器…
③ 划分功能区        以每颗主芯片为核心划一个区，规划各区在图纸上的位置
④ ┌ 取一个区
  │ 读手册/器件参数   搞清核心芯片的引脚功能：哪些是输入、输出、电源、地
  │ 放下本区器件      eda_place_component，位置先粗放，下一步会重排
  │ 写出本区网络表    哪个脚接哪个网络 —— 这份声明是后面几步共同的输入
  │ 排布              eda_arrange_block，把网络表当 nets 传进去
  │ 块内连线          eda_wire_block，画看得见的导线
  │ 电源与地          eda_label_nets，自动放电源符号、地符号
  │ 跨区信号          eda_add_net_identifier 放 IN/OUT 端口，不拉长线
  │ 未用引脚          eda_mark_nc
  │ 画区框            eda_draw_zone，写上标题和一句说明
  │ 体检              eda_check_schematic + eda_schematic_drc
  └ 下一个区
⑤ 区间连接          跨区一律用同名网络标签，不拉长线
⑥ 整体验收          全图 DRC + 通读一遍
```

**一个区做完再做下一个**。这样每次只需要关心十来个器件的关系，摆得准；
出了问题也能立刻定位，而不是最后面对一张乱图不知从何查起。

### 用地图时同理：分层，不要一次算完

走 `eda-schematic-map` 那条路（地图 + 算法布局）时，这条节奏一样成立，
只是换了个名字叫**层**：先摆核心芯片并把它的电源地符号扇出去，那块地方
随即成为硬约束，下一层的器件被算法挡在外面。

```
eda_map_apply({ layer: 1 })                        核心芯片 ＋ 它的扇出
eda_map_apply({ layer: 2, incremental: true })     外围器件，自动避开上一层
```

**为什么不能一次画完**：芯片的引脚展开区是芯片的一部分，该由别人避开它。
一次性模式下扇出排在最后，只能在别人留下的缝里挤 —— 那样怎么补避让都是
治症状。层号写在地图的 `part.layer` 上，细节见 eda-schematic-map skill。

### 需要时去读器件手册

摆之前如果不确定引脚功能，用 `eda_component_detail` 看参数，
必要时 `eda_download_datasheet` 把手册下下来读。

尤其要搞清楚的是：**哪几个脚是输入、哪几个是输出、电源和地在哪一侧**。
不知道这些就没法决定芯片朝向，也没法判断外围器件该放哪边 ——
乱摆的代价是后面连线绕远，返工比先花两分钟看手册贵得多。

### 极性：API 靠不住，必须自己确认

**EDA 的接口分不出极性电容的正负极。** 这是实测结论，不是猜测：

| 器件 | 引脚名 | 能不能判 |
|---|---|---|
| LED / 二极管 | `1=A`、`2=K` | 能 —— 阳极阴极写在名字里 |
| 芯片 | `4=GND`、`8=VCC` | 能 |
| 无极性 MLCC | `1=1`、`2=2` | 本来就没有极性 |
| **钽电容 / 电解电容** | **`1=1`、`2=2`** | **不能** |

钽电容明明有极性，引脚名却和无极性 MLCC 一模一样；`pinType` 只有 `IN`，
`pinShape` 是 `None`，**整个引脚对象里没有任何一个字段表示极性**。

接反的后果：DRC 一声不吭，实物上电就炸。所以按这个顺序处理：

1. **先查手册** —— `eda_component_detail` 看描述，`eda_download_datasheet`
   下手册。绝大多数情况看完手册就能确定，这一步不要省。
2. **查不到就按惯例画，但要标出来** —— 惯例是极性电容 `pin1 = 正极`。
   在器件旁边放一条文字注明「C3 极性按 pin1=+ 假定，请核对手册」。
3. **收尾时汇总** —— 画完把所有「靠惯例假定的极性」列成一份清单交给用户，
   别混在一堆正常输出里一带而过。用户要拿着这份清单去核对。

判断某个器件要不要走这套：**引脚名是纯数字（`1`/`2`）、而器件类别又是
有极性的那类**（电解电容、钽电容、二极管、LED、部分连接器）—— 就要走。

## 每种连接用对应的图形，别一律贴标签

这是让图「像张正经原理图」的关键。把所有连接都写成「每个引脚贴一个网络名」，
电气上成立，看起来是灾难：芯片相邻引脚间距只有 10（0.1 inch），
而一个网络名的文字宽度动辄 30 以上，密集芯片周围必然糊成一团，
连引脚名都被盖住。

| 这个连接是什么 | 就用什么图形 | 工具 |
|---|---|---|
| 电源 / 地 | 电源符号、地符号 | `eda_label_nets`（自动识别并放符号）|
| 同一个功能块内部 | **看得见的导线** | `eda_wire_block` |
| 跨功能区的信号 | 输入/输出端口 | `eda_add_net_identifier` 的 `port_in`/`port_out` |
| 未使用的引脚 | NC 标记 | `eda_mark_nc` |
| 功能区本身 | 矩形框 + 标题 + 说明 | `eda_draw_zone` |
| 实在没法归类的 | 网络标签（兜底）| `eda_label_nets` 自动降级 |

**文字标签是兜底，不是默认。** 判断顺序：先看是不是电源地（用符号），
再看两端是否同区（同区画线、跨区用端口），最后才轮到文字。

一份 nets 声明可以喂给 `eda_arrange_block`（定方位）、`eda_wire_block`（画线）、
`eda_label_nets`（放符号）—— 写一次，用三处，摆位依据和电气连接始终是同一套东西。

### 电源和地：永远用符号

`eda_label_nets` 按网络名自动判断：`GND`/`VSS` → 地符号，`AGND` → 模拟地，
`VCC`/`VDD`/`+3V3`/`+24V` → 电源符号。判断不对时用 `power_nets` 手工指定。

好处不只是好看：电源地是引脚最多的网络，换成符号能一次消掉大半文字重叠；
而且同名符号自动相连，跨区供电不需要拉任何线。

### 未用引脚要明确标出来

裸露悬空的引脚，读图的人分不清是**有意不接**还是**画漏了**。芯片的 NC 空脚、
未用的逻辑门输出、单向使用的收发器接收端，都该 `eda_mark_nc` 打上标记，
并在 `eda_check_schematic` 的 `allow_floating` 里列出来。

## 头对头，不要头对屁股

这是摆放阶段最重要的一条，**决定了线好不好走**。

两个器件要连起来时，让**参与连接的那两个引脚彼此相对**：

```
好：  [U1]OUT →      ← IN[U2]        线是直的，最短
      U1 输出朝右，U2 输入朝左，面对面

坏：  [U1]OUT →      [U2]OUT →       U2 的输入在它背面
      线得从 U1 绕过 U2 整个身子再拐回来
```

具体做法：

- **信号自左向右流**，那么大部分芯片保持默认朝向（输入在左、输出在右）就是对的
- 遇到信号要往回走的场合（比如反馈支路），把那个器件 **`mirror: true`** 翻过来，
  让它的输入朝右 —— 翻转比旋转 180° 好，旋转会把文字也转倒
- **串在信号路径上的电阻**：顺着信号方向放。水平走线用水平电阻，
  垂直走线用 `rotation: 90`，别让一个横着的电阻卡在竖直路径上
- **去耦电容**竖放贴在芯片电源脚旁边，上端接电源、下端接地
- **上拉/下拉电阻**：上拉放在芯片上方、下拉放在下方，一眼能看出是拉高还是拉低

### 判断依据是引脚坐标

摆之前先用 `eda_component_pins` 看核心芯片每个引脚的坐标和 `rotation`
（0 朝右、90 朝上、180 朝左、270 朝下）。要接到某个朝左引脚上的器件，
就该放在芯片左边，且它自己的连接引脚要朝右。

`eda_arrange_block` 已经按这个规则实现了块内排布：它读引脚方位决定外围器件放哪一侧，
并用符号的实际尺寸（bbox）定间距。**但朝向仍要你把关** ——
工具不知道你的信号是往哪个方向流。

### 顺序不能颠倒：先写网络表，再排布，最后标注

器件刚放下时，图上**一条网络都还没有**。工具无从知道 C11 是接在 VIN 还是 VOUT 上，
只能把所有外围器件堆到同一边（实测七个器件排成一列，直接顶出图框）。
所以必须先把本区的网络表写出来，当 `nets` 传给 `eda_arrange_block`：

```
nets = {
  "+24V_IN": ["F3.1"],
  "+24V":    ["F3.2", "U4.1", "C11.1", "C12.1", "U1.3"],
  "+3V3":    ["U1.2", "U1.4", "C13.1", "C18.1"],
  "GND":     ["U1.1", "U4.2", "C11.2", "C12.2", "C13.2", "C18.2", "L1.1"],
  "AGND":    ["L1.2"],
}
eda_arrange_block(core:"U1", members:[…], center_x:450, center_y:220, nets:nets)
eda_label_nets(nets:nets)       # 同一份，原样再传一次
```

**反过来做是错的**：标注会在引脚旁画出短导线，之后再移动器件，导线留在原地，连接就断了。

### 别拿符号的引脚布局想当然

摆之前一定要 `eda_component_pins` 看一眼。实测 AMS1117 的符号里
**VIN / VOUT / ADJ 三个脚全在左侧**，右边只有一个 TAB —— 跟"输入左、输出右"的直觉相反。
这类符号的外围器件会全归到一侧，块中心就要往另一边挪，给那一侧留出两三列的空间
（`eda_arrange_block` 会自动换列，但留不留得下空间是你定的）。

## 怎么划功能区

### 以芯片为核心

绝大多数功能块的形态是「一颗 IC + 它的外围无源器件」。先列出所有 IC，
每颗 IC 起一个块，再把电阻电容电感二极管归到"它服务的那颗 IC"。

判断归属看它连的信号网络：`U5` 的输出端接了 `R15/R16`，那 R15/R16 属于 U5 这块。
只接电源和地的去耦电容，归到它物理上靠近的那颗 IC。

### 常见功能区

| 区 | 典型器件 | 图纸位置惯例 |
|---|---|---|
| 电源 | LDO/DCDC（AMS1117、TPS、MP 系列）、输入保护、储能电容 | **左上或顶部**，单独成区 |
| 接口/连接器 | 端子、RJ45、BNC、USB、排针 | **图纸左右边缘**，信号进的放左、出的放右 |
| 保护 | TVS、保险丝、共模电感、ESD | 紧挨对应的接口，在接口和内部电路之间 |
| 基准/偏置 | 电压基准（REF30xx）、恒流源（LM334） | 靠近它服务的模拟电路 |
| 模拟前端 | 运放、仪表放大器、滤波 RC | **左中部**，跟着信号流向 |
| 转换 | ADC、DAC、V/F 转换（LM331） | 模拟区和数字区**之间** |
| 数字核心 | MCU、FPGA、逻辑门、存储 | **中部偏右** |
| 时钟 | 晶振、谐振器及其负载电容 | **紧贴 MCU**，越近越好 |
| 通信 | RS485/CAN 收发器、以太网 PHY | **右侧**，靠近对应接口 |

### 分区的两个检验标准

- **块内高内聚**：同一块里的器件之间连线多，块内走线短
- **块间低耦合**：跨块的信号少，且能用网络标签表达，不需要长线穿越

如果某个块内器件之间几乎没有连线，说明分错了；如果两个块之间有十几条线，
它们本来就该是一个块。

### 放不下就把区拆细，别硬塞

布局跑完如果 trace 报「所有分区横向共需 XXXX，图纸只有 YYYY 可用」或者
「分区 X 越出图纸」，**不要靠调 anchor 硬挤**（anchor 是软约束，挤不出
空间来，只会让退火结果更差）。正确的动作是**把最大的那个区按功能拆开**。

一个真实例子：ATTINY85 的 IO 区放了 R2/R3/LED1/LED2/SW2/R4 六个器件，
每个都挂电源或地符号、每个符号都要预留引出空间，结果这个区被撑成
220×1040 的长条，直接顶出 A3 图纸。按功能拆成「状态指示」（两路 LED
支路）和「用户按键」（按键加上拉）两个区之后，变成 340×300 和 260×160，
轻松放下 —— 而且图更好读，因为这本来就是两件事。

判断信号：**一个区超过 5 个器件、或者某边尺寸超过图纸的一半**，
就该想想它是不是混了两种功能。分区是你的判断，算法只负责把你分好的区摆下。

## 图纸位置怎么排

### 信号从左到右流

这是最重要的一条阅读惯例：**输入在左，输出在右**。
传感器/接口 → 保护 → 调理 → 转换 → 处理 → 输出接口，从左往右排开。

一张 4-20mA 变送器的典型排布：

```
┌─────────────┬──────────────┬─────────────┬────────────┐
│ 电源区       │              │             │            │
│ AMS1117+去耦 │              │             │            │
├─────────────┤  模拟前端     │  V/F 转换   │  MCU 区    │
│ 输入接口     │  运放/基准    │  LM331      │  ATTINY85  │
│ +TVS 保护   │              │  多路开关    │  +晶振     │
├─────────────┼──────────────┼─────────────┼────────────┤
│             │              │             │ RS485 收发  │
│             │              │             │ +输出接口   │
└─────────────┴──────────────┴─────────────┴────────────┘
```

### 块内摆放交给 eda_arrange_block

划好功能块之后，**块内谁放左、谁放右不用你算** —— 调 `eda_arrange_block`：

```
eda_arrange_block(core:"U5", members:["R15","R16","R17","D4","C19"], center_x:600, center_y:400)
```

它做两件你手算很容易出错的事：

1. **读符号的实际尺寸**（bbox）来定间距。固定间距在大芯片上必然重叠 ——
   14 脚的 RJ45、17 脚的 CD4052，符号比常见间距大得多。
2. **按引脚方位放外围器件**：某个电阻接在核心的左侧引脚上，就放到核心左边；
   接地的放下方，接电源的放上方。芯片左右各有电容时自然分到两侧，
   而不是排成"芯片、电容、电容"一条线。

这部分是纯几何计算，依据是引脚坐标，所以交给工具；
**哪些器件属于同一块仍然是你的判断**，工具不会替你分。

### 区域尺寸留够

单位是 0.01 inch。经验值：

- 器件间距 **80–120**（0.8–1.2 inch），小于 60 会挤在一起、连线无处可走
- 功能区之间留 **150 以上**空白，让跨区连线有通道
- 一个 5–8 件的功能块，大约占 400×400 的方块

图纸放不下就换大的：`eda_set_page_size(size:"A3")`（A4 约 1170×825，A3 约 1650×1170）。
**先设图纸再放器件**，否则器件会掉到图框外。

## 器件方向惯例

方向错了，图会立刻显得业余：

- **电源符号朝上，地符号朝下** —— 这是最强的视觉约定，任何时候不要违反
- **IC 的输入在左、输出在右**，必要时用 `mirror` 翻转而不是旋转 180°
- **串在信号路径上的电阻**：水平信号用水平放置，垂直信号用垂直放置（`rotation: 90`）
- **去耦电容**：竖放，上端接电源、下端接地，紧贴 IC 电源引脚
- 同一块里的同类器件保持同一朝向，看起来才整齐

`eda_arrange_components` 支持批量传 `{designator, x, y, rotation, mirror}`。

## 跨区连接用网络标签

同一块内的器件，靠 `eda_auto_route` 画实线连起来。

**跨功能区不要拉实线** —— 长线穿越图纸是可读性的头号杀手。用网络标签：
两端引脚各自 `eda_label_pin_net` 声明同一个网络名，同名网络自动电气相连。

电源和地更是如此：**永远不要为 VCC/GND 拉线**，一律用电源符号
（`eda_add_net_identifier` 的 `power` / `ground` / `analog_ground`）。

网络命名要有意义：`ADC_IN`、`RS485_A`、`VREF_2V5` 这样一眼看懂用途的名字，
比 `NET1`、`$1N3811` 强得多；后续查网表、跑 DRC 时也省事。

## 完整示例：逐区闭环

以 4-20mA 变送器为例，做完一个区再进下一个。

```
# ── 准备 ──
eda_set_page_size(size:"A3")          # 先设图纸，否则器件会掉到图框外

# ── 第 1 区：电源 +24V→3.3V ──
eda_component_detail(designator:"U1")  # 不熟悉就先看 AMS1117 的引脚定义
eda_place_component(lcsc_id:"C347222", x:200, y:150, designator:"U1")
eda_place_component(...)                # C11/C18 去耦
eda_arrange_block(core:"U1", members:["C11","C18"], center_x:200, center_y:150)
eda_label_pin_net(designator:"U1", pin:"3", net:"VIN_24V")
eda_label_pin_net(designator:"U1", pin:"2", net:"VCC_3V3")
eda_auto_route
eda_schematic_drc                       # 这一区先干净了再往下走

# ── 第 2 区：模拟前端 ──
# 同样的循环：查引脚 → 摆核心 → 摆外围 → 声明网络 → 布线 → DRC
...

# ── 区间连接 ──
# 不拉线，两端各自声明同名网络即可
eda_label_pin_net(designator:"U5", pin:"1", net:"OPA_OUT")
eda_label_pin_net(designator:"U8", pin:"12", net:"OPA_OUT")

# ── 整体验收 ──
eda_schematic_drc
eda_schematic_nets                      # 对一遍网络数与关键网络的连接
```

## 布线会扯断连接，必须核对

`eda_auto_route` 让图好看，代价是**它重组走线时会把导线从引脚上扯掉**。
实测一次全图布线后，148 个引脚只剩 60 个还连着 —— 而 `eda_schematic_drc`
照样报 errors: 0，器件、网络名、连线在图上一个不少，肉眼和 DRC 都发现不了。

所以调用时**必须把 nets 声明传进去**：

```
eda_auto_route(nets: nets)      # 和 arrange_block / label_nets 同一份
```

工具会在布线后逐个引脚核对，把被扯断的接回来，并在 `repaired_after_routing`
里告诉你修了几个。不传就只布线不校验，**断了不会有人告诉你**。

一份网络表用在三个地方：排布定方位、标注建连接、布线后兜底核对。

### 别拿 DRC 当连接的证据

DRC 查的是「已有网络之间有没有冲突」，查不出「引脚压根没进任何网络」。
一个引脚悬空、一整块电路孤立，DRC 都可能一声不吭。

要确认连接，看 `eda_auto_route` 返回的 `repaired_after_routing` 和
`still_disconnected`；收尾时再核一遍每个器件的引脚是不是都落在网络里。
**未连的引脚应该只剩你有意悬空的那些**（NC 空脚、未用的逻辑门输出、
单向使用的收发器接收端），其余都得有网络。

## 什么时候可以用 eda_auto_layout

`eda_auto_layout` 是让 EDA 算法排布全部器件。它**不理解功能分区**，只按连接关系排。

- 器件很少（十来个）、又不想费心规划时：可以用
- **复刻已有图纸**：不要用，会打乱原布局
- **正经设计**：不要用，分区是设计的一部分，交给算法等于放弃设计

用了之后布局变了，要重新跑 `eda_auto_route`。

## 画完必须跑体检

`eda_check_schematic` 是**每张图交出去之前的最后一道关**，它查四件肉眼容易漏的事：

- **引脚是否真的连上**（几何判据：引脚坐标到导线线段的距离；落在导线中间的
  T 型分支也算连上）
- **文字是否重叠**（按字号估外接框两两相交）
- **器件是否重叠**（bbox 相交）
- **是否出了图框**

把有意悬空的引脚填进 `allow_floating`，剩下的 `floating_unexpected` 就该是空的。

**不要拿 DRC 当连接的证据。** DRC 查的是已有网络之间有没有冲突，
查不出「引脚压根没进任何网络」—— 实测一次全图布线后 148 个引脚只剩 60 个
还连着，DRC 照样报 errors 0。

## 几个实测出来的坑

- **y 轴向上为正**：y 越大越靠图纸上方。摆「电源在上、地在下」时别按屏幕坐标想。
- **每种电源地符号的原生朝向不同**，`createNetFlag` 没有通用的「角度→视觉方向」
  映射，而且入参与读回的 `component.rotation` 在 90/270 上是反的（传 90 存成 270）。
  标定表（本体朝向 → rot 参数）：`Ground` 下=0 左=90 上=180 右=270，**`Power` 恒
  差 180°**。要定别的符号的朝向，在真机空白处摆 rot 0/90/180/270 一排人眼确认，
  别从别的符号推 —— 曾经拿地符号量出的映射套到电源上，把电源符号翻了个个儿，
  图上电源和地全朝下，而所有自检都是绿的。
- **符号朝向分两种场景**，判据是簇里有几个引脚（簇 = 同器件同引出方向的一组）：
  独苗（阻容的电源地脚）按语义朝向，Power 本体朝上、Ground 本体朝下；密集扇出
  （多引脚芯片同侧）本体**一律伸向阶梯变短的那一侧**（水平引出朝下、垂直引出朝左），
  不看空间。混用会出事：拿阶梯规则套独苗，电容的 +3V3 符号本体往下伸就压回电容
  身上；拿语义朝向套密集扇出，同侧一上一下，朝上的那些必然穿过上方更长的那根线。
- **判断器件朝向要看引脚，不要看位号文字**。位号文字（`sch_PrimitiveAttribute`
  的 `Designator` 项）确实带 x/y 且随器件旋转，但**只区分横竖、不区分正反** ——
  0° 与 180° 的文字偏移完全相同，镜像也不改变它。而「电源朝上还是朝下」正好是
  180° 之差。引脚四个角度四个值：配合 y 轴向上为正，`pin.rotation=90` 朝上、
  `270` 朝下。
- **画框给两个对角点就行**，`eda_draw_zone` 内部会转换 —— 底层
  `sch_PrimitiveRectangle.create` 的签名其实是 (topLeftX, topLeftY, width, height)，
  直接按两点式调会画出一个跑到图纸外的巨框。
- **区标题写在框内**：区框常紧贴图纸边缘，标题往框外挪一点就掉出图纸了。
- **位号只在当前页内唯一**：同一工程的其他 Board 不会占用你的位号。
- **符号的引脚布局别想当然**：实测 AMS1117 的 VIN / VOUT / ADJ **三个脚全在左侧**，
  跟「输入左、输出右」的直觉相反。摆之前一定 `eda_component_pins` 看一眼。
- **LED、二极管注意极性方向**：阳极要朝着电流来的那一侧。方向不对就 `mirror`，
  别用旋转 180°（文字会跟着倒过来）。
