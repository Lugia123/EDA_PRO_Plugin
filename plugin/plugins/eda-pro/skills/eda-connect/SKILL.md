# 连接立创EDA专业版

AI 通过两段链路操作 EDA：MCP 进程内的 bridge（WebSocket 服务端） ← EDA 里的 `eda-bridge` 扩展主动连过来。
**扩展必须由用户装在 EDA 里**，桌面客户端和网页版都支持。

## 判断当前状态

任何时候先调 `eda_status`。三种结果：

| 返回 | 含义 | 下一步 |
|---|---|---|
| `connected_clients` 非空 | 一切正常 | 直接干活 |
| 空 + `paired: true` | 装过也配对过，只是此刻没连上 | 见「连不上」 |
| 空 + `paired: false` | 从未配对 | 见「首次配对」 |

## 首次配对

1. 让用户构建并导入扩展：`eext-eda-bridge/` 里 `npm run build` → `build/dist/*.eext`
   → EDA 里「高级 → 扩展管理器 → 已安装 → 导入」
2. **让用户在扩展管理器里勾选「允许外部交互」**——这步最容易漏。不勾的话 `SYS_WebSocket.register()`
   直接抛异常，扩展连尝试连接都做不到。建议同时勾「显示在顶部菜单」，否则用户找不到配对入口。
3. 让用户刷新网页版页面（或重启客户端）——扩展在 `onStartupFinished` 激活，不刷新不加载
4. 调 `eda_pair_start` 拿 6 位码，**原样告诉用户**
5. 用户在 EDA 顶部「EDA Bridge → 配对(P)...」输入
6. 调 `eda_status` 确认

配对码 5 分钟有效、最多 5 次、成功即废。配对后签发长期 token，之后重连自动认证，不用再输。

## 连不上的排查顺序

按这个顺序问，不要跳：

1. **EDA 里有「EDA Bridge」顶部菜单吗？**
   没有 → 扩展没装、没启用、或没勾「显示在顶部菜单」；也可能装完没刷新页面
2. **点「EDA Bridge → 连接状态」显示什么？**
   - 「外部交互权限：未开启」→ 去扩展管理器勾选，然后点「重新连接」
   - 「未连接」→ MCP 侧 bridge 可能没起来，让用户重启 Claude Code 会话
   - 「已连接，等待配对」→ 走 `eda_pair_start`
3. **刚才是不是重启过 MCP / 换过端口？**
   扩展靠心跳发现断线，**最长要 45 秒**才会察觉并重扫端口。等一会儿，或让用户点「重新连接」立即触发
4. **token 失效**（换机器、对方 `eda_unpair` 过）
   扩展会提示「保存的配对凭证已失效」，重新走一次配对即可

## 端口

bridge 用 `49630-49639`，启动时选第一个可用的。这段是特意避开官方 `run-api-gateway` 的
`49620-49629`，两者可以同时装、互不干扰。

如果十个端口全被占（极少见），`eda_status` 会报错，需要用户排查占用进程。

## 多个 EDA 同时开着

桌面客户端和网页版可以同时连上同一个 bridge。`eda_status` 的 `connected_clients` 会列出全部，
`active: true` 的那个接收所有执行请求（默认是最后认证成功的）。

**操作前若用户同时开着两个，先用 `eda_status` 确认 active 的是不是 TA 想要的那个**，
避免改错地方。区分方式看 `host` 字段：`desktop` 是客户端，`web` 是网页版。

## 安全边界

配对不是形式主义。实测：任意网站的 JS 都能连本机 `ws://127.0.0.1`（Chrome 视 loopback 为可信来源，
不拦混合内容），而本 MCP 能在 EDA 里执行任意代码。所以：

- 未配对的连接除握手外什么都做不了，60 秒不认证即断开
- 用户报告「莫名其妙弹出配对提示」时，提醒 TA **不要**输入不是自己发起的配对码
- 怀疑泄露就 `eda_unpair`，token 立即失效、所有连接断开
