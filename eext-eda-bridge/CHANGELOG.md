# EDA Bridge 更新日志

立创EDA专业版扩展，把 EDA 接入本机的 eda-mcp。
版本号的 patch 位由构建脚本自动刷成当前 git commit 数。

## 0.1.18

### 修正

1. 提示框长时间不消失、反复重连时堆叠盖住画布。
   `sys_Message.showToastMessage` 的 `timer` 参数单位是**秒**（官方注释：「自动关闭倒计时秒数」），
   此前按毫秒传了 4000/8000，等于让提示挂 66 分钟到 2 小时。

### 变更

1. 重新界定什么时候该弹提示：自动重连成功不再打扰用户（状态可从「连接状态」菜单查看），
   只有手动点「重新连接」才回一句；「待配对」提示在同一状态里只弹一次，
   端口反复扫描不会刷屏。配对成功、凭证失效、配对失败等仍会提示。
2. 清理官方脚手架残留：`CHANGELOG.md` / `README.md` 换成本扩展自己的，
   删掉官方的 en/ja/ru/zh-Hant 四份 README，`package.json` 身份由 `pro-api-sdk / 1.6.4`
   改为 `eda-bridge`。
3. 版本号改由仓库根的 `scripts/stamp-version.mjs` 统一维护，扩展、MCP、plugin、
   marketplace 五处版本号必定一致。
4. 发版流程固化为项目 skill（`.claude/skills/release/`），含版本号规则、
   CHANGELOG 写入时机、以及「哪些改动需要用户重新导入扩展」的判断表。

## 0.1.14

### 修正

1. `send()` 失败时不再把 `lastMessageAt` 清零。此前这会让下一次心跳立即判定连接已死并重连，
   把正在执行的请求打断——表现为「每写一步就断一次」。真断线时自然收不到消息，
   心跳会按 `DEAD_AFTER_MS` 正常判定，不需要人为催促。

## 0.1.13

### 变更

1. 版本号 patch 位改为自动跟随 git commit 数，便于按版本号定位到具体代码

### 修正

1. `send()` 失败不再误置「无外部交互权限」标志。此前连接一断 `send` 必然抛错，
   于是扩展认定没有权限、跳过所有端口，**永久放弃重连**（只能靠刷新页面恢复）。
   权限问题现在只以 `register()` 抛错为准。
2. `connect()` 中 `close` 与随后的 `register` 之间加入等待，消除同一 WS_ID 的竞态。
   此前新连接刚认证通过就会被旧连接的关闭事件带走（日志表现为认证通过后立刻 `code=1000`）。

## 0.1.0

首个版本。

### 新功能

1. 自动扫描 `49630-49639` 发现 bridge（避开官方 run-api-gateway 的 `49620-49629`，可共存）
2. 配对码换长期 token，凭证存 `SYS_Storage`，重连自动认证
3. 接收 AI 下发的代码在 EDA 内执行并回传结果，返回值做循环引用 / 类实例 / BigInt 处理
4. 心跳保活与断线重连
5. 顶部菜单：配对 / 重新连接 / 断开连接 / 连接状态 / 解除配对 / 关于

### 已知限制

1. `SYS_WebSocket.register()` 不提供 onClose / onError 回调，断线只能靠超时判定
2. 重新导入扩展会清空 `SYS_Storage`，配对凭证丢失需重新配对（扩展权限则会保留）
