# 全面检查报告 · 2026-08-08

覆盖设计、扩展、MCP、skill 四块。**本轮只诊断不修改**。

问题按「会不会让人白干活」排序 —— 能默默产出错误结果的排在前面，
因为那种问题比直接报错危险得多：你以为成了，其实没成。

规模参考：MCP 侧 6596 行 TypeScript（布局内核 1593 行）、48 个工具、8 份 skill。

---

## A · 阻断级：会毁掉已有成果

### A1 · 删除图元会让整页永久不可写

**现象**：`sch_PrimitiveComponent.delete` / `sch_PrimitiveWire.delete` 会让扩展断连。
若批量删除在中途断开，此后该页**所有写操作**永久失败：

```
modify        → Cannot destructure property 'cmdKey' of 'i' as it is undefined
Text.create   → 返回空
Wire.create   → create failed!
```

`cmdKey` 属于 EDA 的命令系统（undo/redo 用），它 undefined 说明命令上下文已损坏。

**关键特征**：
- **刷新页面无效**，必须关闭标签页重新打开
- 损坏状态**跟着文档走**，不跟标签页 —— 换标签页打开同一页仍然不可写
- 只读操作照常，所以体检、导入都还能跑，很容易误判为「工具好着呢」

**实测代价**：T5 页在本轮彻底报废，重跑了三次才确认不是参数问题、不是缓存、
不是焦点问题。

**影响**：`eda_map_apply` 的「清场重画」策略从根上不成立。它开头就要删几十个图元。

### A2 · `eda_map_apply` 不能连着调第二次

第一次成功后，图上已有导线和符号；第二次调用先清场，删到中途断连，
后续步骤全部失败，**而第一次的成果已经被删了一半**。

实测：T6 第一次 apply 完体检「悬空 0」，第二次 apply 后变成「悬空 20」。
**净效果是倒退**。

分步执行只让失败可见，没有解决问题：

```
清导线      {"removed": 0}       ← 这步就断了
清符号与端口  {"failed": ...}
摆器件      {"failed": ...}
画导线      {"failed": ...}
```

### A3 · 「当前活动文档」会静默切换

MCP 的所有原理图工具都作用于「当前活动文档」，而一个标签页里可以开多个文档，
活动的那个会在你不知道的时候变。

实测：导航到 T3 的 URL，`getCurrentSchematicPageInfo` 报的却是 T5 的 uuid。
于是 `eda_map_import` 读的是 T3、`eda_check_schematic` 查的是 T5，
两份结果对不上，白排查一轮。

**没有任何工具在返回值里带上它操作的页 uuid**，调用方无从核对。

## B · 严重：产出错误结果且不报错

### B1 · 布线穿越他人引脚造成误连（已修，但要留意判据）

原理图里导线经过引脚就算连上。A* 起初只把器件本体当障碍，引脚格是挖开的
（为了让线出得来），于是线会**路过别的器件的引脚**。

实测：RESET 的走线路过去耦电容 C2 的引脚，反向导入时 C2 就进了 RESET 网络。
**DRC 一声不吭，肉眼只看到两条线挨得近。**

已改为「本网络的引脚可踩，别人的不行」。但要注意这条判据依赖引脚坐标对齐网格，
若引脚落在非网格点上仍可能漏。

### B2 · 反向导入的网络归属不可靠

`eda_map_import` 靠几何判定引脚归属（点到线段距离 < 2）。两个固有缺陷：

1. **图上真有误连时，它如实导出误连** —— 这是对的行为，但调用方容易当成算法错
2. **电源地要从符号做连通搜索**，而搜索会顺着线段扩散。实测 `+3V3` 一度吞掉
   整个 RESET 网络的成员。限定为「只走不带网络名的线段」后好转，
   但电容两脚仍会被算进同一网络

**结论**：导入只能当初稿，网络归属**必须** AI 逐条核对。工具描述里写了，
但没有机制强制。

### B3 · 体检曾漏检符号重叠（已修）

`eda_check_schematic` 原来只收集 `componentType === 'part'` 的包围盒，
`netflag` / `netport` 完全没参与重叠检测。于是「器件被地符号压住」这类最常见的
压叠被判为通过 —— 用户一眼看出的三处重叠，体检报「通过」。

**假阳性的体检比不体检更坏**：它让人停止检查。

### B4 · 图纸尺寸读不到，导致大面积误判出框

`titleBlockData` 里的 `Width` / `Height` 实测常返回 null（缓存或字段结构问题），
读不到就退回 A4 1170×825。于是 A3 上画的图被判成大批出框：

```
出框: ['U1(250,885..341,921)', 'C1(142,890..159,911)', ... 共 20 余项]
```

`eda_check_schematic` 已加 `sheet` 参数可覆盖，但**默认行为仍会误报**，
而调用方不一定知道要传。

### B5 · 文字位置算了但落不到图上

`sch_PrimitiveAttribute.getAll()` 在扩展上下文里返回 0 条（同 `sch_Net`、
`getPrimitivesInRegion` 的失效模式），所以**位号、型号的位置改不了**。

布局算法优化了 `labelSlots` 并写回地图，但 EDA 上的文字不会动。
优化仍有价值（它让退火知道文字要占地方，从而选出文字不重叠的器件布局 ——
实测顺带把竖放器件从 1/7 提到 5/7），但**地图与图纸在这一项上永久不一致**。

## C · 设计问题

### C1 · 「清场重画」是错误的渲染策略

由 A1/A2 直接推出。删除既慢又危险，而 apply 每次都要删干净重画。

可能的方向（未验证）：
- **复用**：已有的导线和符号尽量 modify 而非删除重建
- **增量**：算出与上次结果的差异，只改动变化的部分
- **分批加确认**：每删几个就确认页面仍可写，不行就停下来报告

### C2 · MCP 60 秒超时与长任务矛盾

SDK 默认 60 秒判超时，而渲染一张十几器件的图要跑几分钟（几十次 EDA 写操作，
中间还会因删图元触发重连）。开发用的 daemon 已放宽到 15 分钟，
但**真实使用时 Claude Code 那一侧的超时管不了**。

超时不等于失败 —— 动作还在执行，只是拿不到回包，反而让人误判工具坏了。

方向：把 apply 拆成若干个独立的 MCP 工具，让 AI 分步调用，每步都在 60 秒内。

### C3 · 地图的图纸尺寸与实际图纸会不一致

`meta.sheet` 是导入时读的，而读不到就填默认 A4。之后布局按地图的尺寸算，
渲染时又不校验实际图纸。实测 T5 的地图记着 A4 而图纸是 A3，
布局白白挤在半张纸上。

缺一个「地图 sheet 与实际图纸不符就报警」的检查。

### C4 · 两套布局工具功能重叠

`eda_optimize_layout` 与 `eda_map_apply` 都做布局+布线：
前者从 EDA 现状读、AI 传 nets；后者从地图读。前者不支持分区，后者支持。

留着两个会让 AI 不知道该用哪个。应当明确：`eda_map_apply` 是正路，
`eda_optimize_layout` 要么删掉，要么退化成它的薄封装。

### C5 · 48 个工具，粒度不齐

有 `eda_execute` 这种可以干任何事的，也有 `eda_mark_nc` 这种只做一件小事的。
`eda_label_pin_net` 与 `eda_label_nets`、`eda_connect_pins` 与 `eda_wire_block`
都是单个/批量的重复。工具越多，AI 选错的概率越大。

### C6 · 代价函数的权重全是硬编码经验值

`partOverlap: 8`、`crossing: 400`、`supplyDir: 60`、`spread: 4`…… 这些数字是
逐次实测调出来的，写在代码里。换一类电路（比如全是大芯片，或全是无源器件）
未必合适，而调它需要改代码重新构建。

而且**它们之间的相对关系没有文档**：为什么交叉是重叠的 50 倍？只有注释里零散提了。

### C7 · 扩展重连不可靠

即使 0.1.25 修掉了固定 WS_ID 和 permissionDenied 的问题，重连仍需人工介入：
页面在后台时 Chrome 把 `setInterval` 节流到分钟级，45 秒的判死心跳形同虚设。
实测多次等待 2 分钟仍未重连，靠刷新页面或点菜单才恢复。

平台层面 `register()` 没有 onClose 回调，这是根因，绕不过去；
但可以用 Page Visibility API 在页面转为可见时立刻重连 —— **一直在待办里没做**。

### C8 · 没有自动化测试

`scripts/test-mcp.ts` 有 93 条断言，但那是针对早期只读工具的；
布局内核 1593 行**没有一行单测**，全靠 `layout-poc.ts` / `group-poc.ts`
两个手动脚本看输出。

布局算法恰恰是最该有单测的：纯函数、无副作用、离线可跑。
现在改一个权重要靠肉眼比对 PoC 输出。

## D · skill 问题

### D1 · 电气参数校验始终缺失

这是**最该补而一直没补**的一项。上一轮我自己设计的 V2.0_Encoder 有三处硬错误：

| 错误 | 后果 |
|---|---|
| AMS1117 输入接 24V（最大 15V） | 烧器件；且 24V→3.3V 线性稳压 100mA 要耗散 2W，SOT-223 扛不住 |
| LM331 用 3.3V 供电（最低 4.0V） | 整条 V/F 链路不工作 |
| LM334 恒流源串在 4-20mA 环路主路径 | 与变送器的电流调制冲突，信号出不来 |

skill 里只有一句软绵绵的「需要时读器件手册」。应该是硬性检查：
**每颗芯片放下之前，供电电压范围、输入耐压、功耗必须对着手册核过**。
`eda_component_detail` 能拿到参数，但没有任何流程要求去看。

### D2 · 新旧 skill 并存，边界靠一段话维持

`eda-schematic-layout`（手工布局准则）与 `eda-schematic-map`（地图工作流）
内容有重叠。已在旧的开头加了指引，但两份都描述「怎么画原理图」，
AI 可能读了旧的就开始手算坐标。

### D3 · 回归文档的结论已过期

`docs/test-circuits.md` 记着 T1–T5 全部通过，但那是**体检口径变严之前**测的：
当时不检查符号重叠、图纸尺寸也按 A4 判。这些结论现在不可信，
而文档里没有任何提示。

### D4 · 五个测试电路都没在新流程下验证过

本轮改了布线判据、加了分组布局、换了渲染路径，但 T1/T2/T4 一次没重测。
T5 页已损坏（A1），T3 结果被覆盖，只有临时建的 T6 走通了一遍完整流程 ——
**而 T6 只有 5 个器件、1 个分区**，覆盖不到分组拼接、跨区端口这些新能力。

## E · 已修但值得记住的坑

这些已经修掉，列在这里是因为它们代表了几类反复出现的错误模式。

| 坑 | 教训 |
|---|---|
| `sch_PrimitiveText.create(x, y, text)` 坐标在前，我一直按 `(text,x,y)` 传 | **API 签名先实测**。传错不报错，文字被当坐标，图元飞到天边，表现为「图上什么都没有」—— T5 的分区标题从来没画出来过 |
| `sch_PrimitiveRectangle.create(topLeftX, topLeftY, width, height)` 不是两点式 | 同上。按两点传会画出跑到图纸外的巨框 |
| 模板字符串吃掉 `\d` `\+` `\n` | **传给 EDA 的代码里不许有反斜杠转义**。踩了三次：两次正则、一次 `split('\n')`（`\n` 是有效转义，会被求值成真实换行，让字符串断行） |
| `getDocumentSource()` / `getCurrentSchematicPageInfo()` 有缓存 | 紧跟写操作去读会拿到旧内容。实测因此漏判：读出 135 个引脚连着，缓存刷新后真实数字是 60 |
| 连接判定只比导线端点 | 引脚落在导线**中间**是合法的 T 型分支。只比端点会大量误判 |
| 位号唯一性跨越整个工程 | `getAll(undefined, true)` 连别的 Board 都算，于是新板放 C1 会被顶成 C2 |
| 写操作断连后自动重试 | 重试一个已生效的写操作等于做两遍。实测多出 U2、U7 两个器件和一个残缺器件 |
| 电源符号与导线各标一次网络名 | 同一个网络名画两遍，挤在一小段线的两端 |
| 两个网络从相邻引脚引出、折返到同一 x | 导线重合＝电气相连，反馈电阻被整个旁路，DRC 不报 |

## F · 优先级建议

不做修改，只列建议顺序。

**必须先解决**（否则整条链路不可用）：
1. A1/A2/C1 —— 渲染策略。删除既毁页面又断连，「清场重画」这条路走不通
2. A3 —— 工具返回值带上操作的页 uuid，让调用方能核对

**紧接着**：
3. C2 —— apply 拆成多个 60 秒内的工具
4. D1 —— skill 补电气参数硬性检查（三处硬错误摆在那里）
5. C8 —— 布局内核补单测，它是纯函数，成本最低收益最高

**然后**：
6. B4/C3 —— 图纸尺寸的真相源统一到地图，并加不符报警
7. C4/C5 —— 收敛工具集，明确 `eda_map_apply` 是正路
8. D3/D4 —— 回归文档标注失效，五个电路在新流程下重测

**长期**：
9. C6 —— 权重外置为可配置，并写清相对关系的依据
10. C7 —— 扩展加 Page Visibility 重连（需要用户重新导入）
